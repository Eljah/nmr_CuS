# Совместная температурная проверка четырёх линий ЯКР

Автономный модуль Java 17 / Maven. Он читает архивные численные частоты, проверяет ранги температурных изменений, сравнивает общую и раздельные температурные функции и проверяет необходимые условия тензорной модели с периодом четыре. Внешние Java-библиотеки не требуются.

Главный результат и точные границы интерпретации: [ANALYSIS_RU.md](ANALYSIS_RU.md). Происхождение входа: [INPUT_PROVENANCE_RU.md](INPUT_PROVENANCE_RU.md).

## Сборка и запуск

Нужны полный JDK 17 или новее и Maven 3.9 или новее. Компиляция Maven использует `--release 17`. Первая сборка Maven загружает стандартные плагины; сам расчёт работает без сети.

Linux/macOS, из корня репозитория:

```bash
cd theory/joint_temperature
mvn clean package
java -jar target/joint-temperature-1.0.0.jar
```

Windows, обычная командная строка:

```bat
cd theory\joint_temperature
mvn clean package
java -jar target\joint-temperature-1.0.0.jar
```

Обход Maven для среды, где плагины недоступны: `sh run.sh` или `run.cmd`. Скрипты сначала ищут `javac`, затем пробуют модуль `jdk.compiler` полного JDK. Переменная `JOINT_JAVA` может задавать абсолютный путь к исполняемому `java`. Вариант без launcher `javac` использует `-source 17 -target 17`; для строгой проверки доступности API Java 17 предпочтительна Maven-сборка с `--release 17`.

Точка входа поддерживает два необязательных позиционных аргумента:

```text
JointTemperature [путь-к-temperature_series.csv [каталог-результатов]]
```

Контрольная сумма входа проверяется: произвольный новый набор нельзя незаметно выдать за этот архивный набор. Для анализа новых данных следует сначала обновить документ происхождения и ожидаемую SHA-256 в программе.

## Что выполняет программа

1. Проверяет SHA-256, количество температур, наблюдений и полных квартетов, затем выполняет независимые численные контрольные задачи.
2. Применяет две заранее заданные версии меток: исходные s1–s4 и обмен s3↔s4 при `T >= 230 K`. Обмен затрагивает и пустые ячейки. Все 89 наблюдений сохраняются.
3. Для 18 полных квартетов вычисляет SVD-эквивалентные ранговые приближения ν и ν² после трёх видов центрирования. Повторяет расчёт для температур до 160 K, от 77 K и при последовательном исключении одной температуры.
4. По всем 89 наблюдениям подгоняет `a_i + b_i/(exp(Theta/T)-1)` с общей или раздельными `Theta`, а также `a_i + b_i (T/100 K)^2`. Выполняет заранее определённую проверку с исключением четырёх температурных блоков.
5. Для каждого варианта меток проверяет все три неэквивалентных глобальных класса противоположных пар четырёх подъячеек. Порядок фиксирован на всём температурном ряду.
6. Проверяет направление первой гармоники ν², второе тождество тензорной модели и ограничения Gram. Строит дополнительную физически допустимую **условную** проекцию: наблюдаемый коэффициент второй гармоники сохраняется, направление первой гармоники определяется TLS, затем подбираются два общих коэффициента с ограничениями.

Последний расчёт не является глобальной оптимизацией всех компонент тензоров и всех скрытых температурных параметров. Проверка с исключённым блоком в этом разделе использует измеренные гармоники исключённого квартета; она проверяет переносимость ограничений между температурами. Предсказание частот только по температуре выполняется в отдельном разделе температурных законов.

## Файлы результатов

| Файл в `results/` | Содержание |
|---|---|
| `transformed_series.csv` | Наблюдения, ν² и центрирование; пропуски остаются пустыми |
| `rank_summary.csv` | Сингулярные значения, доля нормы, RMS и максимальные остатки |
| `rank_modes.csv` | Правые сингулярные векторы, то есть фиксированные пространственные профили |
| `rank_reconstructions.csv` | Все поэлементные восстановления ранга 1 и 2 |
| `rank_omit_one.csv` | Чувствительность ранговых результатов к одной температуре |
| `thermal_parameters.csv` | Все параметры полного и блочного температурных fits |
| `thermal_scores.csv` | Ошибки обучения и исключённых блоков, включая объединённую проверку |
| `thermal_predictions.csv` | Поэлементные прогнозы и остатки; столбец `partition` различает train/test |
| `tensor_coefficients.csv` | Измеренные дискретные гармоники ν² для трёх фиксированных порядков |
| `tensor_summary.csv` | Необходимые условия, свободные параметры тождества, Gram и условная проекция |
| `tensor_predictions.csv` | Остатки первой гармоники и условной физической проекции по каждой линии |
| `tensor_block_validation.csv` | Переносимость тензорных ограничений на исключённые блоки |
| `tensor_omit_one.csv` | Чувствительность тензорных результатов к одной температуре |
| `validation_checks.csv` | Контроль источника, известные задачи и независимые численные ориентиры |
| `calculation_manifest.json` | Размеры данных, SHA-256, runtime и границы оптимизации |

Числа записываются с точкой и полной машинной точностью. Такая запись служит воспроизводимости и не означает экспериментальную точность в 15 знаков. Единицы указаны в заголовках. `residual` всегда означает `fitted − observed`.

## Область выводов

Частоты не содержат знака ГЭП, направления его осей или отдельной величины η. Низкий ранг и небольшие остатки не определяют единственную атомную структуру. Вход не содержит ошибок центров линий; программа не рассчитывает p-values и не использует ширину линии как замену ошибки центра. Все сравнения остаются количественными, но описательными.
